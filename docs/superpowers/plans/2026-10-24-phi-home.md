# Phi home implementation plan

The user authorized the home/auth feature and selected copying existing Claude Code customizations. The user also authorized merging the existing PR stack in sequence.

## Dependency order

1. Private home/key primitives and hidden key-entry prompt.
2. In parallel: native path routing, auth orchestration, and customization import.
3. CLI wiring, prepared alongside step 2 and checked after those contracts join.
4. Combined verification, scoped corrections, documentation, and upstream delivery.

Workers use GPT 6 Luna with maximum reasoning effort. Each owns separate files in an isolated worktree. Every commit contains at most 400 added-plus-deleted lines. Keep normal signing and hooks. Keep reports and credentials out of Git.

## Required behavior

- Default home is `~/.phi`; `PHI_HOME` selects an absolute alternative.
- SDK writes/reads, native temporary files, `--continue`, workflow journals, shell artifacts, and replacement sessions use that home consistently.
- First launch accepts a hidden API key, saves it privately, then starts the SDK. Cancel creates no Query.
- Restart loads the saved key. Environment override does not replace it. Auth commands never print a key.
- Initial customization import preserves existing Phi files and excludes prior Anthropic auth and session data.

## Verification

Do not repeat the steady-state load replay or clean install unless an actual related change requires it. Keep native API spending separate from offline checks. Update the acceptance report with exact checked heads and remaining human/native gates.
