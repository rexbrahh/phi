## Review focus

- A resumed workflow reuses its workflow ID but can receive a new task ID. Task-run ordering must not compare workflow IDs. Covered by Tasks 2 and 5.
- A final assistant envelope can precede `content_block_stop`, and several envelopes can share one model-message ID. Covered by Task 2.
- A permission request can abort while another request has keyboard focus. An answer must never reach the wrong request. Covered by Task 3.
- Session replacement can race with history reads, child-process output, and old SDK callbacks. Old results must not alter the new session. Covered by Tasks 1, 5, and 7.
- A tool can print terminal control sequences, invalid UTF-8, or output larger than memory previews. Display must remain safe and complete output reachable. Covered by Tasks 4 and 6.

## Shared behavior contracts

### Launch and configuration

The CLI accepts `--cwd <directory>`, `--resume <uuid>`, `--continue`, `--model <id>`, `--effort <level>`, `--permission-mode <mode>`, repeated `--plugin-dir <path>`, `--max-budget-usd <number>`, `--dangerously-skip-permissions`, `--help`, and `--version`. No positional prompt or piped-input mode is required. `--resume` and `--continue` are mutually exclusive. Reject invalid values before creating an SDK process. Non-TTY input/output gets a short error and exit status 2. Help and version work without a TTY or credentials.

Default cwd is the launch directory. Resolve explicit directories before launch. Use `~/.phi` unless the user sets an absolute `PHI_HOME`. Keep project configuration in the project. Omitted model, effort, and permission mode retain SDK configuration. A bypass mode requires the explicit dangerous-permission flag. Do not infer that flag from a task prompt. Model and runtime preference changes stay session-scoped in v1. A permission-rule update can persist only through an explicitly selected SDK suggestion whose destination the UI displays. Local plugin paths map to the SDK's `plugins` option. Show initialized plugin errors and MCP status rather than assuming discovery succeeded.

Resolve `--continue` to the most recently modified session in the launch directory using SDK listing with `includeWorktrees: false`. If none exists, show that result instead of starting an unrelated conversation. Then use its explicit resume ID. Assign a UUID through `Options.sessionId` for a new session. A fork assigns a new UUID with both `resume` and `forkSession: true`. This gives local receipts a stable session identity before the first model turn.

Use an open `AsyncIterable<SDKUserMessage>`, `includePartialMessages: true`, `forwardSubagentText: true`, `includeHookEvents: true`, `enableFileCheckpointing: true`, `extraArgs: { "replay-user-messages": null }`, and `skills: "all"`. Set `CLAUDE_AGENT_SDK_CLIENT_APP` to `phi/0.1.0` in the inherited child environment. Enable `perTaskStopAffordance: true` only after Task 7 connects its tested registered-task stop control. This affordance does not expose the native Workflow-child callback. Leave AI progress-summary generation off.

Accept account provider `firstParty` and source `ANTHROPIC_API_KEY`, `apiKeyHelper`, or `/login managed key`. Unknown metadata cannot establish the intended route. Display the source and stop prompt submission on mismatch. Never display the key. Initialization can run configured hooks and connect configured servers. The application gate prevents Phi from submitting a prompt through an unintended route. It does not certify credit eligibility.

`startSession(options, callbacks, createQuery?)` returns a `Session` containing the native `query: Query`, `ready: Promise<SDKControlInitializeResponse>`, `done: Promise<void>`, `send(message: SDKUserMessage): void`, and `close(): Promise<void>`. `createQuery` defaults to the imported SDK `query` and exists only for tests. The callbacks are `onMessage(message: SDKMessage)` and `onError(error: unknown)`. The caller supplies permission, elicitation, and cwd-observation callbacks through native `Options`.

Start consuming SDK output immediately. Initialization and output consumption must run concurrently. Do not wait for the first prompt to process callbacks. `send()` rejects before readiness or during shutdown. Starting, closing, and replacing a session are serialized. Close pending input, call native `query.close()`, settle callbacks, and observe reader termination. Report a cleanup failure instead of presenting a clean exit.

### State and identity

`createState(cwd: string): PhiState` creates display state. `applySdkMessage(state: PhiState, message: SDKMessage): void` updates it in place. These functions perform no I/O. State stores native payloads or references to them, without inventing another wire protocol.

Keep process generation separate from conversation ID. A new SDK process invalidates old callbacks and worker requests. A `conversation_reset` changes the conversation view, but does not prove that process-owned tasks stopped. Preserve actual task membership until native events settle it.

Main partial blocks use model-message ID and content-block index. Complete envelopes also have independent UUIDs. Join final blocks to the active block using the documented sequence, content kind, and tool-use ID where present. Do not deduplicate by model-message ID alone. An empty skipped block does not create a duplicate. Unmatched final blocks remain visible. Replays deduplicate by envelope UUID. Apply explicit `supersedes` removals and aborted flags.

Subagent token deltas are not forwarded by this SDK. Group complete child messages by `agent_id` or their known parent tool ID. Do not attach child messages to the main response's active block. Use `session_state_changed` for foreground state. A `result` does not prove that every background task finished.

Submitted input receives a UUID. Track `submitted`, `received`, `consumed`, and `delivery unknown` separately. A user replay can establish receipt. Echoed `user_message_uuid` or `user_message_uuids` establish consumption. Historical echoes do not acknowledge a new submission. Interruption receipts retain the listed submissions. Missing receipts do not prove cancellation.

Task records use `taskId` and optional `taskRunId` from native task events. Within one task, ignore an older nonempty run ID when a newer one is visible. Do not apply an unversioned terminal update over a newer versioned execution. Preserve that event for inspection. Workflow metadata stores `workflowRunId` from `WorkflowOutput.runId` separately. Never order these workflow IDs.

Track tool input completion separately from tool execution. Complete generated arguments establish a requested call. Permission waiting, native progress, and the result establish later states. A known workflow `error` field is a failure even if the enclosing shape contains launch metadata.

Replace live background membership from `background_tasks_changed`. Keep completed records for inspection. Exclude `ambient` tasks from the busy count, but include them in exit cleanup. Unknown events produce an inspectable notice. Do not treat them as successful tools. Use the latest SDK session usage totals, without summing duplicate reports or adding child costs again. Unknown cost stays unknown.

### Interaction and keyboard ownership

`InteractionQueue` exposes native-compatible `canUseTool: NonNullable<Options["canUseTool"]>` and `onElicitation: NonNullable<Options["onElicitation"]>`. It also exposes `pending`, `answer(requestId, response)`, and `cancelAll(reason)`. Use a discriminated pending-request union so tool decisions and elicitation responses cannot cross. IDs come from SDK callbacks. Repeated requests share one pending decision. Abort and answer races settle the promise once.

Tool permission choices are allow once, deny with optional feedback, and SDK-suggested permission updates when available. Respect `suppressAlwaysAllowRule`, `defaultToNo`, and matched ask rules. A rejected or cancelled request never becomes an allow. Do not manufacture a permanent allow rule from command text.

For `AskUserQuestion`, preserve the original questions. Return `updatedInput: { ...input, answers }`, keyed by question text. A single choice uses its label. Multiple choices use an array of labels. Free text uses the actual text. Preselection is not submission. Question previews display as safe text. Preserve draft answers when another request receives focus.

MCP URL elicitation shows the server, message, and URL. Open only an explicitly selected HTTP(S) URL. Form elicitation supports flat string, numeric, boolean, enum, and enum-array fields. Validate required fields, declared types, enums, length/item limits, numeric bounds, and recognized formats. Unknown constraints or nested schemas make the form unsupported. V1 can decline forms with arbitrary regular-expression constraints instead of running untrusted regexes. Show an explanation and decline/cancel options, not guessed values. Follow the [MCP elicitation contract](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation). V1 advertises no `onUserDialog` kinds because their payload contracts are not public typed forms. Permission requests and questions use the documented callbacks above.

| Context | Key | Action |
| --- | --- | --- |
| Composer | Enter; Shift+Enter or Ctrl+J; Up/Down at boundaries | Submit; newline; pi-tui history navigation |
| Anywhere | Escape; Ctrl+C | Dismiss completion/view first, else interrupt foreground work; Ctrl+C interrupts active foreground work, otherwise opens exit when work or a draft remains |
| Work and views | Ctrl+B; Ctrl+T; Ctrl+O; Ctrl+Shift+P | Native backgrounding; tasks; transcript inspector; palette |
| Attachments and job control | Ctrl+V; Ctrl+Z | Read a clipboard image on explicit action; suspend terminal UI and restore it on SIGCONT |
| Dialog or inspector | Tab/Shift+Tab, arrows, Space, Enter, Escape | Move focus, navigate, select, submit explicitly, or dismiss without approving |

All local actions also have `/phi` command access. Terminal Cmd+C/Cmd+V remain native selection and text paste. Modal focus may leave the composer temporarily inaccessible, but must preserve its draft. A pending question can remain visible without trapping the user in it.

### Output, files, and limits

Use pi-tui's `Editor`, `Markdown`, `Text`, `SelectList`, `Input`, `CombinedAutocompleteProvider`, and width utilities. Main-screen mode owns no mouse scrolling. The terminal owns conversation scrollback. Inspectors use bounded rows, keyboard paging, and pi-tui wrapping. Do not use alternate-screen-only layout APIs in this renderer.

The composer records complete bracketed-paste packets supplied by pi-tui, without another terminal input parser. Supply surviving normalized pastes through `inline_pastes` where they still match the submitted text. Use the editor's expanded text, not its paste markers. On failed local submission, restore the text and attachments that the editor cleared before its callback.

Text files use native `@path` mentions. Image attachments use typed SDK image blocks. Validate PNG, JPEG, GIF, and WebP signatures, not just extensions. V1 limits a single image to 5,000,000 bytes and all attachments in one submission to 20,000,000 bytes. These are explicit application limits. They are not claims about every provider limit. Reject larger input without resizing or losing the draft. Clipboard image acquisition uses macOS AppKit through the installed `osascript`, only when the user requests it. Clipboard content must not appear in logs or tests.

Strip untrusted terminal sequences before Markdown or text rendering. Remove remaining C0/C1 control characters except newline and tab. Use pi-tui formatting only after sanitization. Render link text without automatically opening it. Copy uses `pbcopy` through stdin on macOS, never interpolated shell text. Use terminal selection as the fallback.

Tool previews show at most 12 lines and 8,192 characters. Complete native results remain available through SDK history or their native output references. Retain bounded completed-tool previews and native IDs instead of retaining every full result body in the main UI. Keep only one selected child history page in the UI. Redraw requests use pi-tui's coalescing. Do not launch a custom frame timer unless the load test identifies a need.
